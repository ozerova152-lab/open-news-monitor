# Запуск и настройка Open News Monitor

## Безопасный первый запуск

1. Установите Python 3.11 или новее.
2. В папке репозитория выполните `pip install -e .`.
3. Проверьте шаблон: `python -m open_news_monitor validate examples/ai-work-monitor.json`.
4. Запустите без записи и рассылок: `python -m open_news_monitor run examples/ai-work-monitor.json --dry-run`.

`--dry-run` показывает найденные карточки, но не создаёт базу, не меняет Google Sheets и не отправляет сообщения.

### Windows: самый простой путь

После скачивания репозитория откройте PowerShell в его папке и выполните:

```powershell
.\scripts\setup-windows.ps1
.\scripts\create-monitor.ps1 -Name my-monitor
```

Первый скрипт только создаёт локальное окружение и устанавливает агент. Второй запускает мастер создания личного мониторинга. Ни один из них не отправляет новости, не создаёт Telegram-бота и не запрашивает секреты.

## Что хранится на GitHub, а что остаётся только на компьютере

В GitHub-репозитории хранятся код, документация, тесты и безопасные примеры. Личный профиль нужно создать в `config/local/`; эта папка исключена из Git. Там могут находиться персональные источники, правила отбора и выбор каналов доставки. Токены бота, chat ID, пароли SMTP и ключ Google всегда остаются только в локальном `.env`.

## Создание профиля без ручного JSON

Вместо редактирования файла вручную запустите:

```bash
python -m open_news_monitor init-monitor config/local/my-monitor.json
```

Мастер спросит название, ссылки на источники, правила отбора и удобный способ получения новостей: Google Sheets, Telegram, email или несколько каналов одновременно. Каждую ссылку он проверит тем же транспортом, что использует агент. Источник без подтверждённых заголовков, ссылок и дат не попадёт в новый профиль.

Markdown-дайджест и локальная база создаются всегда. Для Telegram после выбора укажите в `.env` токен бота и ID чата; для email — SMTP-настройки; для Google Sheets — ID таблицы в мастере и путь к ключу сервисного аккаунта в `.env`. До появления этих локальных данных ни один канал не сможет выполнить отправку.

## Источники

Поддерживаются RSS, Atom, публичные HTML-страницы новостей и открытые JSON-эндпоинты. Добавляйте только те источники, на чтение которых у вас есть право. Для каждого нового источника сначала выполните dry-run и посмотрите, извлекаются ли заголовок, дата и прямая ссылка.

До добавления в конфигурацию используйте безопасную проверку:

```bash
python -m open_news_monitor check-source https://site.ru/feed.xml --name "Название источника"
```

Она не добавляет источник, не пишет в базу и не отправляет сообщения. Команда подтверждает доступ через реальный RSS-парсер агента и честно отмечает непроверенные границы архива.

Если есть только обычная ссылка на сайт, используйте универсальную проверку:

```powershell
python -m open_news_monitor probe-source https://site.ru/news --name "Новости организации"
```

Она сначала проверит ссылку как RSS/Atom, затем найдёт RSS/Atom, если лента объявлена внутри страницы, затем попробует открытый JSON. Результат будет одним из трёх: **можно подключать**, **нужна доработка** или **подключение следует отложить**. Проверка не добавляет источник, не отправляет сообщения и не обходит защиту сайта.

## Статус работы

После обычного запуска агент сохраняет локальный отчёт о состоянии: время запуска, число новых публикаций, доступность каждого источника и ошибки. Посмотреть его можно так:

```powershell
python -m open_news_monitor status config/local/my-monitor.json
```

Если отчёта ещё нет, это означает, что монитор пока не выполнялся в обычном режиме. Режим `--dry-run` намеренно не меняет рабочее состояние.

Для HTML-источника сначала исследуйте одну повторяющуюся карточку публикации по методике `skills/news-source-research`. В настройке должны быть селекторы `card`, `title`, `link` и `date`, причём все поля берутся из одной карточки. Не добавляйте сайт, если дата или прямая ссылка нестабильны.

Для JSON-источника нужны поля `items`, `title`, `link` и `date`: `items` указывает на список публикаций в ответе API, остальные — на поля одной публикации. Открытый JSON-ответ проверяется тем же транспортом, что и рабочий сборщик; ключи и авторизация не поддерживаются.

## Как настроить личный мониторинг ИИ

1. Скопируйте `examples/ai-work-monitor.json` в `my-ai-monitor.json`.
2. Замените демонстрационный URL на RSS-ленты сайтов, которым доверяете.
3. Добавьте слова в `include_any`; пустой список означает «брать все новые публикации из источника».
4. Добавьте нежелательные слова в `exclude_any`.
5. Запускайте `--dry-run`, пока выдача не станет полезной.
6. Выполните `python -m open_news_monitor run my-ai-monitor.json --initialize`. Этот запуск сохранит текущие публикации как границу и ничего не отправит.
7. Лишь после этого включайте Telegram, email или Google Sheets.

## Telegram и email

Скопируйте `.env.example` в `.env` и заполните только нужные значения. В конфигурации канала поставьте `enabled: true`. Секреты и chat ID не должны попадать в Git.

Для существующего бота создайте `.env` рядом с `README.md`. В нашем тестовом сценарии это будет бот с целевым чатом «Тестовый мониторинг новостей»:

```text
ONM_TELEGRAM_BOT_TOKEN=локальный_токен_бота
ONM_TELEGRAM_CHAT_ID=локальный_id_чата
```

Агент читает `.env` автоматически при запуске. Не присылайте эти значения в чат и не включайте Telegram в JSON-профиле, пока не проверим текст первого тестового сообщения и вы явно не подтвердите отправку.

## Google Sheets

Установите дополнительную зависимость:

```bash
pip install -e ".[sheets]"
```

Создайте сервисный аккаунт Google, скачайте его JSON-ключ за пределы репозитория и дайте email сервисного аккаунта доступ редактора к нужной таблице. Укажите путь к ключу в `ONM_GOOGLE_SERVICE_ACCOUNT_FILE` и `spreadsheet_id` в конфигурации.

Агент добавит в лист строки с полями: статус, дата обнаружения, источник, заголовок, ссылка, краткое описание и причина совпадения. Он не меняет и не удаляет существующие строки.

## Расписание

Планировщик пока остаётся внешним: Windows Task Scheduler, cron или GitHub Actions. Так запуск прозрачен и не требует скрытого фонового процесса. Автоматическое создание расписания будет добавлено после проверки личного профиля.
