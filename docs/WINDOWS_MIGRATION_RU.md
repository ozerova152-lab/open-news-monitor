# Переход действующей рассылки на Windows

Этот сценарий относится только к рабочему профилю `config/local/my-ai-monitor.json`. Все действия с действующей рассылкой выполняются после отдельного согласования. Подготовительный тест использует вымышленные данные и отдельную базу.

1. Выберите окно перехода вне времени доставки. Запишите текущие время и способ запуска и проверьте, что процесс не выполняется. После согласия поставьте прежнюю автоматизацию Codex на паузу. Проверьте, что второго запуска этого профиля нет.
2. Сохраните в защищённой папке рабочий профиль, SQLite и её сопутствующие файлы после остановки записи. Для согласованной копии можно использовать SQLite Backup API. Убедитесь, что копия открывается и содержит историю `SENT`. Секреты храните отдельно с ограниченным доступом.
3. Проверьте новую версию на отдельной копии профиля и базы. Укажите абсолютные пути к копии базы и тестовому Markdown. Отключите внешние каналы и удалите их времена доставки из тестового расписания. Запустите локальную проверку конфигурации и включите `"freshness": {"max_age_hours": 48}`. Выполните инициализацию без доставки. Проверьте, что история `SENT` сохранилась и что архивная очередь удерживается. Просмотрите журнал `history`.
4. Перед изменением рабочего профиля получите согласие. Не пересоздавайте его мастером. Сохраните ссылку на прежнюю SQLite и включите политику свежести. Настройте `schedule.enabled`, `schedule.timezone` со значением `Europe/Moscow` и `schedule.deliver_at.telegram` со значением `["10:00"]`. Укажите интервал сбора. Во время настроек задача Codex должна оставаться на паузе.
5. Покажите имя задачи, путь к профилю, Python, рабочую папку, интервалы и способ отключения. После разрешения выполните `schedule install`. Проверьте `schedule status`. Системная задача проверяет расписание примерно каждые пять минут, поэтому 10:00 — начало окна доставки. Для Windows используется вход текущего пользователя, без повышения прав.
6. До реальной отправки убедитесь на изолированном профиле, что штатная задача создаёт Markdown и историю без открытого Codex как источника запуска. Только после отдельного разрешения проверьте одну рабочую доставку и сопоставьте результат в журнале с полученной подборкой в Telegram.
7. Для отката после согласия отключите новую задачу командой `schedule disable`, дождитесь окончания процесса и сделайте копию **текущей** базы. По возможности оставьте текущую базу, чтобы не утратить `SENT`. Если необходим откат к старой базе, сначала сверьте и перенесите подтверждённые доставки и отложите неоднозначные записи. Проверьте копию без сети. Только затем решайте, включать ли прежнюю автоматизацию. Старую очередь без сверки не запускайте.
