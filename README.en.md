# Open News Monitor

To run with Codex closed, use a system scheduler on a powered-on computer or an always-on Linux server. See the [scheduling guide](docs/SCHEDULING_RU.md) and [server setup](docs/SERVER_SETUP.md).

[Open the project showcase](https://ozerova152-lab.github.io/open-news-monitor/en.html)

Open News Monitor helps you follow publications from public websites and news feeds you choose. You select sources and optional filter words; the program remembers previously seen items and gathers new publications with links to their originals.

It does not search the entire internet, publish news on your behalf, or make editorial decisions. You decide how to use what it finds.

## Get started with one message

1. Open Codex or Claude Code with access to your computer.
2. Copy the message below and send it to the assistant.
3. Answer its questions one at a time. It will help you download the project, check which software you need and set up your first news digest.

```text
Help me install and set up Open News Monitor.
Repository: https://github.com/ozerova152-lab/open-news-monitor
I may not know terminal commands or technical terms. Explain one step at a time in plain language.
Help me download the project to a folder I choose, then read AGENTS.md and follow its instructions.
Ask whether I have sites already or want suggestions based on a topic. If I need suggestions, give me a few links and explain why they fit. Check which sites can be connected. Do not add a source without my confirmation.
Offer a safe first initialization that does not send old publications.
Offer a manual run, a schedule on my computer, or an always-on Linux server. Do not ask me to paste tokens or passwords into chat; wait for my permission before real delivery or setting up a schedule.
```

Start with a digest saved on your computer. You can set up Telegram, email or Google Sheets later.

## What you get

- A personal profile with confirmed sources and optional words to include or exclude.
- A local Markdown digest with titles, dates and original links, plus a report on the last run.
- Local memory so previously seen links are not treated as new. First initialization records current publications without delivering them.
- Optional delivery of new items to Telegram, email or Google Sheets after separate setup. Telegram and email can include a short excerpt of the original description; it is not translated or generated by AI.

The program collects news when run. Automatic operation requires a separately configured and tested scheduler.

## Your sources

The wizard checks RSS/Atom feeds and some public JSON sources. It can sometimes discover a feed advertised by a web page. Check results mean:

| Result | Meaning |
| --- | --- |
| `READY` | Publications with title, date and direct link were confirmed; you can approve adding the source. |
| `NEEDS_SETUP` | Further setup is needed for safe collection. |
| `UNSUPPORTED` | The detected format is not supported by the current collector. |
| `ERROR` | A technical problem prevented the check from completing. |

HTML pages without a discovered feed are not connected automatically: they need separately verified rules. For larger lists there is a [CSV registry guide](docs/SOURCES_CSV_RU.md) (in Russian): UTF-8 with BOM and `;` as the separator. The guide covers Excel 2010 save limitations.

To add a source to an existing monitor, check it separately with `probe-source`. Once confirmed, add it to the profile's source list or its CSV registry. Avoid running the wizard over an existing profile because it writes a new profile file.

## Delivery channels

All channels are optional. Choose them in the wizard or configure them with your assistant. Enter secrets locally, not in chat.

- **Telegram:** a bot, its token and an agreed test chat ID.
- **Email:** SMTP settings, sender details and a test recipient; Gmail is supported through SMTP with an app password.
- **Google Sheets:** a spreadsheet and worksheet, an enabled Google Sheets API, a service account with access to the spreadsheet, and a local JSON key. Install the optional package only after choosing this channel.

Run `doctor` after setup. Separately approve the first real delivery to the chosen test chat, address or spreadsheet. See the [channel setup guide](docs/CHANNELS_RU.md) (in Russian). Telegram and Gmail passed controlled real tests; Google Sheets passed a real test previously, but current access has not been freshly confirmed.

## Automatic scheduling

Without a scheduler, the program runs when you start it. Optional `schedule-tick` performs actions due under the profile; an external task invokes it regularly. On Windows, commands can install, inspect, enable, disable and remove the profile's task. Task changes require explicit consent.

On one Windows computer the initial registration method was denied, but a fallback succeeded. On November 25–27 the scheduled task collected sources and Telegram confirmed a delivery after retries. Verify scheduling on your computer. A temporary Ubuntu WSL timer was tested; macOS launchd and deployment to a separate server remain unverified. Setup and stopping instructions: [scheduling guide](docs/SCHEDULING_RU.md) (in Russian).

## Manual installation

<details>
<summary>Show Windows requirements and commands</summary>

### What you need

- A Windows computer and Python 3.11 or newer; the Windows scripts need the Python launcher `py`.
- Internet access for installation and checking public sources. Git is needed for the download command below; alternatively download the repository as a ZIP archive.
- Addresses of sources you want to follow. One working RSS/Atom feed is enough to start.
- For external delivery, your own Telegram, email or Google Sheets settings. Keep keys and passwords local, not in chat.

Windows setup was checked. Installation and a temporary timer were tested in Ubuntu WSL. A separate Linux server and macOS launchd have not yet been verified. [Linux and macOS instructions](docs/SETUP_UNIX_RU.md) are in Russian.

### Quick start on Windows

A **terminal** is a window where you enter commands. Open PowerShell, paste commands one at a time and press Enter. If the project is already downloaded, start at step 2.

### 1. Download the project

```powershell
git clone https://github.com/ozerova152-lab/open-news-monitor.git
cd open-news-monitor
```

You should now be in the project folder. If Git is not installed, download the repository as a ZIP from GitHub, extract it and open PowerShell in the extracted folder.

### 2. Install dependencies

```powershell
py -3 --version
.\scripts\setup-windows.ps1
```

Python must be version 3.11 or newer. The script creates a local environment and installs the program; it does not create a profile or send anything. If PowerShell blocks scripts, use the manual steps in the [Windows guide](docs/SETUP_RU.md) (in Russian).

### 3. Create your monitor

```powershell
.\scripts\create-monitor.ps1 -Name my-monitor
```

The wizard prompts are currently in Russian. It asks for a monitor name and source URLs one at a time, checks each source and asks whether to add it. At least one confirmed source is required. You can then specify filter words and delivery channels; leave the channel selection empty for local Markdown only.

At the end, the wizard offers to remember current publications as a starting point. Accept if you do not want existing items delivered as new. This step contacts sources but does not deliver publications. Check the result separately if a source is unavailable.

### 4. Check settings and run the monitor

```powershell
.\.venv\Scripts\python.exe -m open_news_monitor doctor config\local\my-monitor.json
```

`doctor` checks local settings without contacting external services. `READY` means local settings are present, not that access to Telegram, email or Google has been verified.

If you skipped initialization, run it before the ordinary run:

```powershell
.\.venv\Scripts\python.exe -m open_news_monitor run config\local\my-monitor.json --initialize
```

After setup and any approved tests of external channels, run collection and check its status:

```powershell
.\.venv\Scripts\python.exe -m open_news_monitor run config\local\my-monitor.json
.\.venv\Scripts\python.exe -m open_news_monitor status config\local\my-monitor.json
```

An ordinary `run` can send new publications to every enabled channel. The profile is stored in `config/local/`; results and memory are stored in `runtime/`.

## If something went wrong

| What happened | What to do |
| --- | --- |
| `py` is missing or Python is too old | Install Python 3.11 or newer, check `py -3 --version`, and repeat setup. |
| PowerShell blocks the script | Use the manual commands in the [Windows guide](docs/SETUP_RU.md) (in Russian). |
| A source cannot be added | Read its check result; try another feed or determine what setup is needed. Do not enable an unconfirmed source. |
| `doctor` reports missing settings | Check the chosen channel in the [setup guide](docs/CHANNELS_RU.md); do not paste secrets into chat. |
| No news appeared | Check `status`: there may be no new items, or a source or channel may have reported an error. |
| CSV opens in one column or text is unreadable | Import it as UTF-8 with `;` as the separator; see the [CSV guide](docs/SOURCES_CSV_RU.md). |
| A Windows task cannot be created | Check the message and [scheduler limitations](docs/SCHEDULING_RU.md); do not elevate privileges without a separate decision. |

## Freshness and history

New wizard profiles use a 48-hour freshness limit. Existing profiles keep their settings until the user agrees to enable it. Items without a reliable date are withheld. Use `open-news-monitor withheld <profile>` to review them and `open-news-monitor history <profile>` to inspect run history.

The optional Telegram no-news notice can be suppressed if sources were not checked successfully or items have uncertain dates. Failed deliveries are retried on schedule, but a lost service response can cause a duplicate. [Details](docs/SCHEDULING_RU.md) (in Russian).
