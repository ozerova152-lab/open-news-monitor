# Open News Monitor

Open News Monitor — открытый универсальный агент для мониторинга новостей. Пользователь сам выбирает тему и публичные источники, а агент проверяет их, запоминает уже обработанные публикации и формирует подборку только из новых материалов.

Это не поиск «всего интернета» и не автопубликация. Агент сохраняет ссылку на первоисточник, но решение о том, как использовать новость, остаётся за человеком.

## Как начать с Codex или Claude Code

1. Скопируйте ссылку на этот GitHub-репозиторий и откройте его в Codex или Claude Code.
2. Напишите помощнику: «Помоги установить и настроить Open News Monitor пошагово».
3. Отвечайте на короткие вопросы о теме, источниках и способе получения новостей.
4. Подтверждайте действия с внешними аккаунтами и реальными тестовыми отправками.

Помощник может выполнить безопасные локальные действия и объяснить остальные. Он не должен просить вставлять в чат токены, пароли или ключи сервисного аккаунта.

## Что уже умеет версия

- проверять ссылку до подключения;
- автоматически подключать RSS/Atom и часть открытых JSON-источников, если реально подтверждены публикации;
- находить RSS/Atom-ленту, указанную на обычном сайте;
- создавать профиль через пошаговый мастер;
- запоминать существующие публикации как безопасную отправную точку;
- не выдавать повторно уже известные ссылки;
- создавать локальную Markdown-подборку и отчёт о состоянии.
- доставлять новые публикации в Telegram, email и Google Sheets через локальные очереди;
- проверять готовность локальной настройки командой `doctor`.
- выполнять сбор и доставку отдельно командами `collect` и `deliver`;
- выполнять действия по профилю расписания командой `schedule-tick`.

Обычные HTML-сайты без готовой RSS/Atom-ленты пока не подключаются автоматически: им нужна отдельная безопасная настройка. Графического интерфейса пока нет.

Telegram, Gmail SMTP и Google Sheets прошли контролируемые реальные тесты и проверку повторного запуска без дубликатов. Это снижает риск потери и повторов, но не даёт абсолютной гарантии внешней доставки при сетевом сбое.

## Первый запуск на Windows

```powershell
.\scripts\setup-windows.ps1
.\scripts\create-monitor.ps1 -Name my-monitor
```

Мастер попросит указать источники, покажет результат проверки и спросит: «Добавить этот источник? Да/Нет». Затем предложит запомнить текущие публикации, чтобы в будущем выдавать только новые. Для подробной инструкции смотрите [docs/SETUP_RU.md](docs/SETUP_RU.md).

Если русское «да» искажается при автоматическом вводе через PowerShell, используйте `yes`. В обычном интерактивном запуске мастер принимает `Да`, `д`, `yes` и `y`.

## Необязательное расписание Windows

В профиль можно добавить раздел `schedule`. Команда `schedule-tick` выполняет только те сборы и доставки, время которых уже наступило; постоянно работающий фоновый процесс не создаётся.

Для установки одной задачи Планировщика под конкретный профиль используйте:

```powershell
.\.venv\Scripts\open-news-monitor.exe schedule install config\local\my-monitor.json
.\.venv\Scripts\open-news-monitor.exe schedule status config\local\my-monitor.json
```

Перед изменением задачи программа показывает профиль, Python, частоту и имя задачи, затем просит явное подтверждение. `schedule disable`, `schedule enable` и `schedule remove` управляют только задачей этого профиля. Создание может быть ограничено локальной политикой Windows; не запускайте его от администратора без отдельного согласия.

После создания профиля проверьте локальную готовность:

```powershell
.\.venv\Scripts\python.exe -m open_news_monitor doctor config\local\my-monitor.json
```

`doctor` не делает сетевых запросов и ничего не отправляет. `ГОТОВО` означает, что нужные локальные настройки присутствуют; это не проверка входа во внешний сервис.

## Проверка ссылки

```powershell
.\.venv\Scripts\python.exe -m open_news_monitor probe-source https://example.org/news
```

Результат `READY` означает, что источник можно подключить после подтверждения. `NEEDS_SETUP` означает, что сайт доступен, но ему нужна отдельная настройка. `UNSUPPORTED` — текущий формат не поддерживается. `ERROR` — проверка не завершилась из-за технической проблемы, а не потому, что сайт обязательно неподдерживаемый.

## Безопасность

Личные профили хранятся в `config/local/`, а токены и пароли — только в локальном `.env`. Эти файлы, как и базы SQLite и результаты запусков, исключены из Git.
